# 4. Авторизация

## Что такое JWT

**JWT** (JSON Web Token) — строка-«пропуск», которую backend выдаёт после успешного входа.
Выглядит так: `eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxIi....подпись`.

Состоит из трёх частей через точку:

1. **Заголовок** — алгоритм подписи (у нас HS256).
2. **Данные** (claims) — id пользователя (`sub`), id организации (`companyId`),
   id сессии (`sid`), время выдачи и истечения.
3. **Подпись** — backend подписывает токен секретным ключом. Подделать токен без ключа нельзя.

Токен живёт **1 час** (`expiresIn: 3600` секунд). Frontend его не расшифровывает,
а просто прикладывает к каждому запросу.

Почему JWT, а не сессии на сервере: backend не хранит состояние пользователя в памяти,
поэтому можно запустить несколько копий backend (требование NFR-SCL-01).

## Регистрация и вход

```text
 Пользователь          Frontend                          Backend
     │  вводит данные     │                                  │
     │───────────────────>│  POST /auth/login {email, pass}  │
     │                    │─────────────────────────────────>│ проверяет пароль (BCrypt)
     │                    │  { accessToken, expiresIn,       │
     │                    │    user, company }               │
     │                    │<─────────────────────────────────│
     │                    │ saveSession() → localStorage     │
     │   дашборд          │ router.push('/')                 │
     │<───────────────────│                                  │
```

Регистрация (`POST /auth/register`) работает так же, но одновременно создаёт организацию
и пользователя и сразу возвращает токен — входить отдельно не нужно.

Код: `src/views/LoginView.vue`, `src/views/RegisterView.vue`, `src/api/auth.js`.

## Где хранится токен

В `src/stores/auth.js`:

```js
export const auth = reactive(loadSession())
```

- `auth` — реактивный объект `{ token, expiresAt, user, company }`.
- `saveSession(result)` — записывает ответ сервера и сохраняет копию в `localStorage`.
- `loadSession()` при запуске читает `localStorage`; если токен уже истёк — игнорирует.
- `isLoggedIn()` — есть ли токен и не истёк ли он.
- `clearSession()` — всё стирает.

`localStorage` — хранилище браузера, которое переживает перезагрузку страницы.
Поэтому после F5 пользователь остаётся в системе.

## Как токен попадает в запросы

Перехватчик в `src/api/http.js` добавляет заголовок к **каждому** запросу:

```http
Authorization: Bearer eyJhbGciOi...
```

Backend по этому заголовку понимает, кто делает запрос и из какой он организации.
Поэтому пользователь видит только данные своей организации (FR-02, NFR-SEC-04) —
это гарантирует backend, frontend тут ничего не фильтрует.

## Что происходит, когда токен истёк

Два уровня защиты:

1. **Роутер** (`src/router/index.js`) перед каждым переходом проверяет `isLoggedIn()`.
   Если токен истёк по времени — отправляет на `/login`.
2. **Перехватчик ответа** — если сервер всё же ответил `401` (например, сессию отозвали),
   очищает сессию и перенаправляет на `/login`.

Исключение — сами запросы входа и регистрации: там `401` означает «неверный пароль»,
и нужно показать ошибку, а не перенаправлять.

## Выход

Кнопка «Выйти» в `AppSidebar.vue`:

1. `POST /auth/logout` — backend записывает id сессии в таблицу отозванных.
   С этого момента токен не работает, даже если его кто-то скопировал.
2. `clearSession()` — стираем токен у себя. Делается в `finally`, то есть даже если
   сервер не ответил.
3. Переход на `/login`.

## Ограничения backend, о которых полезно знать

- Пароль — от 8 до 72 байт (ограничение алгоритма BCrypt).
- Email уникален во всей системе: повторная регистрация → `EMAIL_ALREADY_EXISTS`.
- Не больше 20 попыток входа/регистрации в минуту с одного IP → `TOO_MANY_REQUESTS`.
- Пароли хранятся только в виде BCrypt-хэшей (NFR-SEC-01).
