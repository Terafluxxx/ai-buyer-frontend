# 6. Рекомендации по закупке

## Откуда формула

В backend есть класс `RecommendationCalculator.java` — расчётное ядро рекомендаций.
Но REST-метода, который бы его вызывал, пока нет. Чтобы дашборд и рекомендации работали
уже сейчас, формула перенесена во frontend **один в один**: `src/utils/recommendation.js`.

Когда backend добавит эндпоинт рекомендаций, клиентский расчёт нужно заменить запросом к API —
формулы совпадают, поэтому результаты не изменятся.

## Входные данные

| Величина | Откуда |
| --- | --- |
| `sales30` — продано за 30 дней | сумма продаж с 30 дней назад по вчера (`GET /sales`) |
| `stock` — остаток | `GET /inventory` |
| `leadDays` — срок поставки | от поставщика; поставщиков нет, поэтому **7 дней** (значение по умолчанию в backend) |
| `minimumOrder` — минимальная партия | от поставщика; по умолчанию **1** |
| `incoming` — уже заказано | из закупок; закупок нет, поэтому **0** |

Берутся **30 завершённых дней** — сегодняшний день не учитывается, потому что он ещё не закончился.

## Формулы

```text
Средние продажи в день   = sales30 / 30
Точка заказа             = средние продажи × (срок поставки + 7)
Целевой запас            = средние продажи × (срок поставки + 30)
На сколько дней хватит   = остаток / средние продажи
```

- **Точка заказа** — уровень остатка, при котором пора заказывать: товара должно хватить
  на время доставки плюс неделю запаса.
- **Целевой запас** — сколько товара хотим иметь после закупки: на время доставки и ещё месяц продаж.

## Состояние товара (FR-09)

Проверки идут по порядку, срабатывает первая подходящая:

| Состояние | Условие | Смысл |
| --- | --- | --- |
| `NO_SALES` — нет продаж | за 30 дней ничего не продано | спроса нет, считать нечего |
| `CRITICAL` — критично | остаток ≤ продажи за время поставки | товар закончится раньше, чем приедет новая партия |
| `NEED_PURCHASE` — нужна закупка | остаток ≤ точка заказа | пора заказывать |
| `NORMAL` — в норме | иначе | запаса достаточно |

В коде сравнения делаются в целых числах (всё умножено на 30), как в backend:

```js
stock * 30 <= sales30 * leadDays          // CRITICAL
stock * 30 <= sales30 * (leadDays + 7)    // NEED_PURCHASE
```

Это нужно, чтобы дробные числа не дали ошибку округления ровно на границе.
Например, `0.1 + 0.2` в JavaScript равно `0.30000000000000004`.

## Сколько купить

Только для `CRITICAL` и `NEED_PURCHASE`:

```text
Купить = округлить вверх( целевой запас − остаток − уже заказано )
```

Не меньше минимальной партии. Для `NORMAL` и `NO_SALES` — 0.

## Пример

Молоко: остаток **5**, продано за 30 дней **90** (по 3 в день), срок поставки 7 дней.

```text
Средние продажи  = 90 / 30         = 3 шт./день
Продажи за поставку = 3 × 7         = 21
Точка заказа     = 3 × (7 + 7)     = 42
Целевой запас    = 3 × (7 + 30)    = 111
Хватит на        = 5 / 3           ≈ 1,67 дня

Остаток 5 ≤ 21  →  CRITICAL
Купить = 111 − 5 − 0 = 106 шт.
```

Объяснение, которое увидит пользователь по кнопке «Почему?»:

> Остаток 5 шт., средние продажи 3 шт./день, срок поставки 7 дней. Уже заказано 0 шт.
> Рекомендуется купить 106 шт. Поставщик не выбран, бюджет неизвестен.

Ещё примеры из демо-данных:

| Товар | Остаток | В день | Продажи за поставку | Точка заказа | Состояние | Купить |
| --- | --- | --- | --- | --- | --- | --- |
| Кофе | 2 | 2 | 14 | 28 | CRITICAL | 74 − 2 = 72 |
| Хлеб | 30 | 3 | 21 | 42 | NEED_PURCHASE | 111 − 30 = 81 |
| Сыр | 40 | 1 | 7 | 14 | NORMAL | 0 |
| Чай | 12 | 0 | — | — | NO_SALES | 0 |

## Где что в коде

- `src/utils/recommendation.js` — сама формула, функция `calculateRecommendation()`.
- `src/composables/useAnalysis.js` — загружает данные, суммирует продажи по товарам,
  вызывает формулу для каждого товара, сортирует (сначала критичные).
- `src/views/RecommendationsView.vue` и `DashboardView.vue` — показывают результат.
- `src/components/StatusBadge.vue` — цветная метка состояния.

## Ограничения текущей реализации

- Расчёт на клиенте загружает **все** товары и продажи за 30 дней. Для MVP это нормально,
  но при 10 000 товаров (NFR-PERF-04) это должен делать backend.
- Нет поставщиков → срок поставки всегда 7 дней, стоимость и бюджет не считаются.
- Нет закупок → «уже заказано» всегда 0.
