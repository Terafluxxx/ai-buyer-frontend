# 2. Библиотеки и как они работают

В проекте всего три библиотеки для работы приложения и один инструмент сборки:

| Библиотека | Для чего | Где в проекте |
| --- | --- | --- |
| **Vue 3** | Строит интерфейс из компонентов | все файлы `.vue` |
| **Vue Router** | Переключает страницы без перезагрузки | `src/router/index.js` |
| **Axios** | Отправляет HTTP-запросы к backend | `src/api/` |
| **Vite** | Запускает dev-сервер и собирает проект | `vite.config.js` |

Список зависимостей лежит в `package.json`. Команда `npm install` скачивает их в папку `node_modules`.

## Vue 3

Vue — фреймворк для создания интерфейсов. Главная идея: **интерфейс — это функция от данных**.
Мы меняем данные — Vue сам перерисовывает нужные части страницы. Вручную искать элементы
и менять их (как в чистом JavaScript через `document.querySelector`) не нужно.

### Однофайловый компонент (SFC)

Каждый файл `.vue` — это компонент, кусочек интерфейса. Он состоит из трёх частей:

```vue
<script setup>
// 1. Логика: данные и функции
</script>

<template>
  <!-- 2. Разметка: HTML с особыми атрибутами Vue -->
</template>

<style scoped>
/* 3. Стили. scoped — действуют только внутри этого компонента */
</style>
```

`<script setup>` — короткая запись: всё, что объявлено в скрипте, сразу доступно в шаблоне.

### Реактивность: `ref`, `reactive`, `computed`

**Реактивные данные** — это переменные, за изменениями которых Vue следит.

```js
import { ref, reactive, computed } from 'vue'

const loading = ref(false)            // одно значение
loading.value = true                  // в скрипте — через .value

const form = reactive({ email: '', password: '' })  // объект
form.email = 'a@b.ru'                 // без .value

const count = computed(() => rows.value.length)     // вычисляемое значение
```

- `ref` — для отдельных значений (строка, число, массив, объект целиком). В шаблоне `.value` писать не нужно.
- `reactive` — для объекта с полями, например формы.
- `computed` — значение, которое считается из других и само пересчитывается при их изменении.
  Пример: `visibleRows` в `RecommendationsView.vue` — список, отфильтрованный по выбранному состоянию.

`watch` следит за значением и выполняет код при его изменении. Пример — `ProductForm.vue`:
когда приходят новые данные товара, форма заполняется ими.

### Директивы шаблона

| Директива | Что делает | Пример из проекта |
| --- | --- | --- |
| `{{ }}` | Выводит значение | `{{ product.name }}` |
| `v-if` / `v-else` | Показывает элемент по условию | `<p v-if="error">` — ошибка видна, только если она есть |
| `v-for` | Повторяет элемент для каждого элемента массива | строки таблиц товаров |
| `v-model` | Связывает поле ввода с переменной в обе стороны | `<input v-model="email">` |
| `v-model.number` | То же, но превращает ввод в число | поле количества |
| `:атрибут` | Подставляет значение в атрибут (сокращение `v-bind`) | `:disabled="loading"` |
| `@событие` | Подписка на событие (сокращение `v-on`) | `@click="onLogout"` |
| `@submit.prevent` | Обработать отправку формы без перезагрузки страницы | все формы |

### Props и emit — как компоненты общаются

- **Props** — данные, которые родитель передаёт ребёнку (сверху вниз).
- **Emit** — события, которыми ребёнок сообщает родителю (снизу вверх).

Пример: `AppPagination.vue`.

```vue
<!-- Родитель (ProductsView) передаёт номер страницы и слушает событие change -->
<AppPagination :page="result.page" :total-pages="result.totalPages" @change="load" />
```

```js
// Ребёнок (AppPagination) объявляет props и события
const props = defineProps({ page: Number, totalPages: Number })
const emit = defineEmits(['change'])
emit('change', 2)  // родитель вызовет load(2)
```

Так один компонент пагинации используется на трёх разных страницах.

### Слоты

`<slot />` — «дырка» в компоненте, куда родитель вставляет свою разметку.
Пример: `AuthCard.vue` рисует рамку и заголовок, а форму входа или регистрации
вставляет страница.

### Жизненный цикл: `onMounted`

`onMounted(fn)` вызывает функцию, когда компонент появился на странице.
Почти все страницы загружают данные с сервера именно там:

```js
onMounted(load)
```

### Composable — переиспользуемая логика

Composable — обычная функция, которая использует `ref`, `computed` и возвращает их.
Так одну и ту же логику можно подключить в несколько компонентов.
В проекте: `src/composables/useAnalysis.js` — загрузка данных и расчёт рекомендаций.
Используется и на дашборде, и на странице рекомендаций.

### Глобальное состояние без библиотек

Обычно для общего состояния используют библиотеку Pinia. Здесь оно одно — данные авторизации,
поэтому хватило `reactive` в отдельном модуле (`src/stores/auth.js`). Все компоненты,
которые его импортируют, видят один и тот же объект.

## Vue Router

Наше приложение — **SPA** (Single Page Application, одностраничное приложение).
Браузер загружает одну HTML-страницу, а переходы между «страницами» делает JavaScript,
без перезагрузки. Vue Router отвечает за то, какой компонент показать для какого адреса.

### Таблица маршрутов

```js
const routes = [
  { path: '/', redirect: '/dashboard' },                         // перенаправление
  { path: '/login', component: LoginView, meta: { public: true } },
  { path: '/products/:id', component: ProductDetailView },       // :id — параметр
  { path: '/:pathMatch(.*)*', redirect: '/' },                   // все неизвестные адреса
]
```

- `meta` — наши произвольные пометки. `public: true` значит «можно без входа».
- `:id` — часть адреса, которая меняется. Читается так: `useRoute().params.id`.

### Компоненты роутера

- `<RouterView />` — место, где показывается текущая страница (в `App.vue`).
- `<RouterLink to="/products">` — ссылка без перезагрузки страницы. Активной ссылке роутер
  сам добавляет класс `router-link-active` — так подсвечивается пункт меню.
- `useRouter().push('/login')` — переход из кода.

### Навигационный guard (страж)

`router.beforeEach` вызывается перед каждым переходом. У нас он не пускает
неавторизованного пользователя на закрытые страницы:

```js
router.beforeEach((to) => {
  if (!to.meta.public && !isLoggedIn()) return '/login'
  if (to.meta.public && isLoggedIn()) return '/'
})
```

### History mode

`createWebHistory()` делает обычные адреса вида `/products/5` (без `#`).
Поэтому production-сервер должен на любой адрес отдавать `index.html` — dev-сервер Vite делает это сам.

## Axios

Axios — библиотека для HTTP-запросов. Удобнее встроенного `fetch`: сам превращает JSON
в объекты, сам выбрасывает ошибку при кодах 4xx/5xx и умеет **перехватчики**.

### Общий экземпляр

В `src/api/http.js` создаётся настроенный экземпляр:

```js
const http = axios.create({ baseURL: '/api/v1' })
```

Теперь `http.get('/products')` отправит запрос на `/api/v1/products`.

### Перехватчики (interceptors)

Перехватчик — функция, которая выполняется для **каждого** запроса или ответа.

- **На запрос** — добавляет токен в заголовок `Authorization`. Без этого пришлось бы
  писать заголовок в каждом из ~20 запросов.
- **На ответ** — если сервер вернул `401`, значит токен недействителен: очищаем сессию
  и отправляем на страницу входа.

### Как выглядит запрос

```js
// GET с параметрами: /api/v1/products?page=0&size=20&q=мол
const { data } = await http.get('/products', { params: { page: 0, size: 20, q: 'мол' } })

// POST с телом
const { data } = await http.post('/products', { sku: 'A-1', name: 'Товар' })
```

`await` ждёт ответа сервера. `data` — уже готовый объект из JSON.
Если сервер вернул ошибку, `await` выбросит исключение — его ловят через `try / catch`:

```js
try {
  await createProduct(product)
} catch (e) {
  error.value = errorMessage(e)   // показать понятный текст
}
```

### Почему запросы вынесены в `src/api/`

Компоненты не знают адресов API — они вызывают функции вроде `getProducts()`.
Если адрес на backend поменяется, править нужно одно место.

## Vite

Vite — инструмент разработки. Он:

1. **Запускает dev-сервер** (`npm run dev`) на `http://127.0.0.1:5173`. При сохранении файла
   страница обновляется мгновенно (Hot Module Replacement).
2. **Превращает `.vue` файлы в JavaScript**, который понимает браузер (через плагин `@vitejs/plugin-vue`).
3. **Собирает production-версию** (`npm run build`) — сжатые файлы в папке `dist/`.

### Proxy и CORS

Frontend работает на порту 5173, backend — на 8080. Для браузера это разные «источники» (origin),
и по правилам безопасности **CORS** он заблокирует запросы, если backend явно их не разрешит.
Backend CORS не настраивает.

Решение — proxy в `vite.config.js`: браузер отправляет запрос на свой же адрес
`127.0.0.1:5173/api/...`, а Vite пересылает его на `localhost:8080`. Для браузера
всё происходит в пределах одного источника, блокировки нет.

```js
proxy: {
  '/api': { target: 'http://localhost:8080', changeOrigin: true },
}
```

В production ту же роль выполняет Nginx.

## npm-скрипты

Описаны в `package.json`, запускаются как `npm run <имя>`:

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер |
| `npm run build` | сборка для production в `dist/` |
| `npm run preview` | посмотреть собранную версию локально |
| `npm run seed` | заполнить backend демо-данными |
