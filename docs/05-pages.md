# 5. Страницы приложения

Для каждой страницы: что умеет и какие запросы к API отправляет.
Все адреса API начинаются с `/api/v1`.

## Общие особенности backend

Чтобы понимать код страниц, полезно знать три правила backend.

### Пагинация

Списки приходят по страницам, а не целиком:

```json
{
  "items": [ ... ],
  "page": 0,
  "size": 20,
  "totalElements": 57,
  "totalPages": 3
}
```

Страницы считаются **с нуля**. Максимальный размер страницы — 100.
За переключение отвечает компонент `AppPagination.vue`.

### Версии записей (optimistic locking)

У товара, остатка и продажи есть поле `version`. При изменении нужно передать текущую версию:

```json
PATCH /products/5   { "name": "Новое имя", "version": 3 }
```

Если за это время кто-то уже изменил запись (версия стала 4), backend ответит
`409 VERSION_CONFLICT`. Так два сотрудника не затрут изменения друг друга.
Frontend всегда берёт `version` из последнего ответа сервера.

### Строгие параметры

Backend отвечает ошибкой 400 на неизвестные или пустые параметры (`?q=`).
Поэтому все параметры проходят через `withoutEmpty()` из `src/utils/params.js`.

## Товары — `/products`

FR-03.

- Поиск по SKU и названию (без учёта регистра, по подстроке).
- Фильтр по категории (точное совпадение).
- Сортировка: по названию А→Я и Я→А, по SKU, сначала новые.
- Кнопка «+ Добавить товар» открывает форму. После создания — переход в карточку.
- Клик по строке открывает карточку товара.
- API:
  - `GET /products?page=&size=&q=&category=&sort=`
  - `POST /products` — `{ sku, name, category }`

SKU уникален внутри организации: при повторе backend вернёт `SKU_ALREADY_EXISTS`.

## Карточка товара — `/products/:id`

Состоит из трёх блоков.

**1. Карточка** (`ProductDetailView.vue`)
- Просмотр: SKU, название, категория, даты создания и изменения.
- Редактирование: в `PATCH` отправляются **только изменённые поля** и `version`.
  Пустая категория отправляется как `null` — так категория удаляется.
- Удаление: `DELETE /products/{id}?version=`. Backend не даст удалить товар,
  у которого есть остаток или продажи (`RESOURCE_IN_USE`).

**2. Остаток** (`ProductInventory.vue`) — FR-04
- Текущее количество и время обновления.
- Изменение: `PUT /products/{id}/inventory` — `{ quantity, version }`.

**3. Продажи** (`ProductSales.vue`) — FR-05
- Сводка и список продаж за последние 30 дней.
- Форма «Записать продажи за день».
- API: `GET /sales/summary`, `GET /sales`, `PUT /products/{id}/sales/{date}`.

## Остатки — `/inventory`

FR-04.

- Таблица остатков всех товаров. В каждой строке — поле для нового количества и кнопка «Сохранить».
- Backend возвращает в остатках только `productId`, поэтому страница отдельно загружает
  справочник всех товаров, чтобы показать названия.
- API: `GET /inventory`, `GET /products` (все страницы), `PUT /products/{id}/inventory`.

## Продажи — `/sales`

FR-05.

- Выбор периода (по умолчанию — последние 30 дней, максимум — 365 дней) и товара.
- Сводка: сколько всего продано и сколько разных товаров продавалось.
- Таблица продаж по дням.
- Кнопка «+ Записать продажи» — форма с выбором товара.
- API: `GET /sales/summary`, `GET /sales`, `PUT /products/{id}/sales/{date}`.

### Как устроена запись продаж

Продажи хранятся **по дням**: одна запись на товар в день.
`PUT /products/{id}/sales/2026-11-01` с `{ quantity: 5, version }` **заменяет** количество за день, а не прибавляет.

Чтобы передать правильную `version`, форма `SaleForm.vue` сначала ищет запись за этот день
(`findSale()` в `src/api/sales.js`):
- записи нет → `version: 0` (создание);
- запись есть → её текущая `version` (обновление).

Важно: продажи **не уменьшают остаток** на складе — так решено в backend.
Дата не может быть в будущем.
