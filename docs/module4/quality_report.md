# Отчёт о контроле качества кода

## 1. Цель

В рамках практической работы была организована система контроля качества frontend-проекта AI Закупщик.

Основные задачи:

- унификация форматирования исходного кода;
- статический анализ JavaScript и Vue-компонентов;
- обнаружение потенциальных ошибок;
- автоматическая проверка изменений перед коммитом;
- устранение замечаний анализаторов.

## 2. Используемые инструменты

| Инструмент        | Назначение                               |
| ----------------- | ---------------------------------------- |
| ESLint            | Статический анализ JavaScript и Vue      |
| Prettier          | Проверка и автоматическое форматирование |
| SonarQube for IDE | Дополнительный анализ качества кода      |
| Husky             | Запуск Git Hooks                         |
| lint-staged       | Проверка подготовленных к коммиту файлов |

## 3. Результаты статического анализа

### ESLint

При первоначальной проверке были обнаружены замечания, связанные с правилами Vue. Для свойств компонента `AuthCard` требовалось определить значения по умолчанию либо сделать свойства обязательными.

Было выбрано решение с явным указанием `required: true` для обязательных свойств `title` и `subtitle`.

После исправлений `npm run lint` завершилась без ошибок и предупреждений.

### SonarQube for IDE

В ходе анализа были обнаружены две проблемы.

#### S9011 — ProductForm.vue

Анализатор указал на отсутствие явно заданного типа у кнопки сохранения формы. Для неё было добавлено:

```html
<button type="submit"></button>
```

Это явно определяет назначение кнопки внутри формы. Кнопка отмены уже имела тип `button`.

#### S9382 — fetchAll.js

Анализатор обнаружил `await` внутри цикла при последовательной загрузке страниц.

Исходная реализация выполняла запросы по очереди. Алгоритм был переработан:

1. Первая страница загружается отдельно.
2. Номера оставшихся страниц формируются заранее.
3. Оставшиеся запросы выполняются параллельно.
4. Количество одновременных запросов ограничено пятью с помощью `p-limit`.
5. Результаты объединяются в исходном порядке.

Для ограничения параллельности используется `MAX_CONCURRENT_REQUESTS = 5`.

Такое решение ускоряет загрузку, не отправляя неограниченное количество запросов одновременно. Изменение оформлено отдельным Pull Request №14 и включено в `main`.

## 4. Проверка Git Hooks

Для автоматического контроля изменений перед коммитом настроены Husky и lint-staged.

Работа механизма проверялась намеренно некорректным JavaScript-кодом с неиспользуемой переменной. ESLint обнаружил нарушение `no-unused-vars`, после чего Git Hook завершился с ошибкой и заблокировал создание коммита.

Таким образом, была подтверждена работоспособность автоматической проверки.

## 6. Вывод

В проекте реализована многоуровневая система контроля качества. Prettier отвечает за единообразное форматирование, ESLint обнаруживает ошибки в исходном коде, SonarQube помогает выявлять потенциальные проблемы, а Husky предотвращает попадание некорректных изменений в историю Git.

В ходе работы были исправлены замечания анализаторов и оптимизирована загрузка страниц в `fetchAll`.
