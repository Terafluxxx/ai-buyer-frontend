# Настройка рабочего окружения

## 1. Цель

Цель настройки рабочего окружения — обеспечить единый стиль оформления исходного кода, автоматическое обнаружение ошибок, проверку изменений перед коммитом и удобное выполнение тестов.

В качестве редактора используется Visual Studio Code. Основной стек проекта — Vue 3, JavaScript и Vite.

## 2. Среда разработки

| Инструмент         | Назначение                           |
| ------------------ | ------------------------------------ |
| Visual Studio Code | Редактор исходного кода              |
| Node.js            | Среда выполнения JavaScript          |
| npm                | Управление зависимостями и скриптами |
| Git                | Контроль версий                      |
| Vue 3              | Разработка интерфейса                |
| Vite               | Запуск и сборка frontend-приложения  |

Используемые расширения VS Code:

| Расширение        | Назначение                          |
| ----------------- | ----------------------------------- |
| Vue Official      | Поддержка Vue-компонентов           |
| Prettier          | Автоматическое форматирование       |
| ESLint            | Статический анализ JavaScript и Vue |
| EditorConfig      | Единые настройки оформления файлов  |
| SonarQube for IDE | Дополнительный статический анализ   |

## 3. Единые правила оформления

### EditorConfig

Файл `.editorconfig` задаёт общие правила:

- кодировка UTF-8;
- окончания строк LF;
- отступы пробелами размером 2 пробела;
- перевод строки в конце файла;
- удаление пробелов в конце строк.

Для Markdown-файлов отключено удаление пробелов в конце строк.

### Prettier

Используется Prettier версии 3.10.1.

Основные настройки `.prettierrc.json`:

| Параметр        | Значение |
| --------------- | -------- |
| `singleQuote`   | `true`   |
| `semi`          | `false`  |
| `printWidth`    | `100`    |
| `tabWidth`      | `2`      |
| `useTabs`       | `false`  |
| `trailingComma` | `es5`    |
| `endOfLine`     | `lf`     |

`.prettierignore` исключает зависимости, результаты сборки, отчёты покрытия и `package-lock.json`.

Команды:

```bash
npm run format
npm run format:check
```

Первая форматирует файлы, вторая проверяет форматирование без изменения файлов.

## 4. Статический анализ

Для проверки JavaScript и Vue используется ESLint. Конфигурация находится в `eslint.config.js` и использует Flat Config.

В неё входят:

- `@eslint/js` — рекомендуемые правила JavaScript;
- `eslint-plugin-vue` — рекомендуемые правила Vue;
- `globals` — глобальные переменные браузера и Node.js;
- `eslint-config-prettier` — отключение конфликтующих правил форматирования.

Для `src/` определено браузерное окружение. Для конфигурационных файлов и скриптов используется окружение Node.js. Каталоги `node_modules`, `dist` и `coverage` исключены.

```bash
npm run lint
npm run lint:fix
```

Первая команда запускает проверку, вторая автоматически исправляет поддерживаемые ESLint ошибки.

## 5. Автоматическая проверка перед коммитом

Для проверок перед коммитом используются Husky 9.1.7 и lint-staged 17.6.1.

В `package.json` определены группы файлов:

- JavaScript и Vue: Prettier, затем ESLint с автоматическим исправлением;
- JSON, CSS, HTML, Markdown и YAML: Prettier.

В `.husky/pre-commit` находится команда:

```bash
npx lint-staged
```

Перед коммитом обрабатываются только подготовленные к коммиту файлы. Это позволяет обнаруживать проблемы до попадания изменений в историю Git.

## 6. Настройка окончания строк

В корне проекта используется `.gitattributes`. Он задаёт автоматическое определение текстовых файлов и принудительное использование LF для основных типов исходников, конфигураций, Markdown и Git Hooks.

Это снижает вероятность появления лишних изменений при работе на разных операционных системах.

## 7. Проверка настройки

После установки зависимостей можно выполнить:

```bash
npm install
npm run format:check
npm run lint
npm run test:run
npm run build
```

Для получения отчёта о покрытии:

```bash
npm run test:coverage
```

HTML-отчёт формируется в каталоге `coverage/`.

## 8. Результат

В проекте настроено единое окружение разработки, автоматическое форматирование, статический анализ и проверка изменений перед коммитом. EditorConfig и Prettier обеспечивают согласованный стиль кода, ESLint помогает обнаруживать потенциальные ошибки, а Husky и lint-staged автоматизируют предварительную проверку изменений.
