# AI Закупщик — Frontend

Веб-интерфейс для системы **«AI Закупщик»** — SaaS-сервиса, который помогает бизнесу планировать закупки.
Система хранит товары, остатки на складе и продажи, анализирует их и подсказывает,
какие товары пора докупить и в каком количестве.

Frontend написан на **Vue 3** и общается с backend
([ai-buyer-backend](https://github.com/Terafluxxx/ai-buyer-backend)) через REST API.

## Что умеет

| Раздел | Возможности |
| --- | --- |
| Вход / регистрация | Регистрация пользователя вместе с организацией, вход по email и паролю (JWT), выход |
| Профиль | Данные пользователя и его организации |
| Товары | Список с поиском по SKU и названию, фильтром по категории, сортировкой и пагинацией; создание товара |
| Карточка товара | Редактирование, удаление, текущий остаток, продажи за 30 дней, запись продаж за день |
| Остатки | Остатки всех товаров с быстрым изменением количества |
| Продажи | Продажи за выбранный период (до 365 дней), фильтр по товару, сводка: сколько продано и сколько товаров продавалось |
| Дашборд | Количество товаров, критических, требующих закупки, без продаж; список товаров к закупке |
| Рекомендации | Состояние каждого товара (`CRITICAL`, `NEED_PURCHASE`, `NORMAL`, `NO_SALES`), средние продажи, дни запаса, точка заказа, целевой запас, сколько купить и текстовое объяснение расчёта |

### Важно про рекомендации

В backend уже есть формула расчёта (`RecommendationCalculator`), но REST-метода для неё пока нет.
Поэтому формула перенесена на клиент один в один: [src/utils/recommendation.js](src/utils/recommendation.js).
Когда в backend появится эндпоинт рекомендаций, этот расчёт нужно будет заменить запросом к API.

Модуля поставщиков пока нет, поэтому срок поставки берётся по умолчанию (7 дней),
а стоимость закупки и бюджет не рассчитываются.

### Что ещё не сделано

Эти функции описаны в требованиях, но backend их пока не поддерживает:

- поставщики и их условия (цена, срок поставки, минимальная партия);
- создание закупок и смена их статусов;
- импорт данных из CSV.

## Технологии

- [Vue 3](https://vuejs.org/) — интерфейс (компоненты в формате `<script setup>`)
- [Vue Router](https://router.vuejs.org/) — переходы между страницами
- [Axios](https://axios-http.com/) — HTTP-запросы к backend
- [Vite](https://vitejs.dev/) — dev-сервер и сборка
- обычный CSS, без UI-библиотек

## Запуск

Понадобятся:

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — для backend и базы данных;
- [Node.js](https://nodejs.org/) версии 18 или новее — для frontend;
- [Git](https://git-scm.com/).

### Шаг 1. Запустить backend

1. Запустите Docker Desktop и дождитесь, пока он полностью загрузится.
2. Скачайте backend:

   ```sh
   git clone https://github.com/Terafluxxx/ai-buyer-backend.git
   cd ai-buyer-backend
   ```

3. Создайте в папке backend файл `.env` с паролем базы данных и секретом для JWT:

   ```dotenv
   DATABASE_PASSWORD=любой-пароль
   JWT_SECRET=сюда-случайная-строка
   ```

   `JWT_SECRET` должен быть base64-строкой от 32 случайных байт. Получить её можно так:

   ```sh
   # Linux / macOS / Git Bash
   openssl rand -base64 32
   ```

   ```powershell
   # Windows PowerShell
   [Convert]::ToBase64String((1..32 | % { Get-Random -Max 256 }) -as [byte[]])
   ```

4. Запустите backend вместе с PostgreSQL:

   ```sh
   docker compose up --build
   ```

   Первый запуск занимает несколько минут. Backend готов, когда в логах появится строка
   `Started MvpApplication`. Он работает на `http://localhost:8080`.

### Шаг 2. Запустить frontend

В новом терминале, в папке этого проекта:

```sh
npm install
npm run dev
```

Откройте в браузере **http://127.0.0.1:5173**.

Dev-сервер Vite перенаправляет все запросы `/api/...` на backend (настройка `proxy` в
[vite.config.js](vite.config.js)). Если backend запущен на другом адресе, укажите его в переменной `API_URL`:

```sh
# Linux / macOS
API_URL=http://192.168.1.10:8080 npm run dev

# Windows PowerShell
$env:API_URL="http://192.168.1.10:8080"; npm run dev
```

### Шаг 3. Загрузить демо-данные

Чтобы не вводить всё вручную, можно заполнить backend готовыми данными (backend должен быть запущен):

```sh
npm run seed
```

Скрипт [scripts/seed-demo.js](scripts/seed-demo.js) создаёт пользователя, организацию, 5 товаров,
их остатки и продажи за последние 30 дней. Повторный запуск ничего не меняет.

**Данные для входа:**

| Поле | Значение |
| --- | --- |
| Email | `demo@demo.ru` |
| Пароль | `demo12345` |
| Организация | Демо-магазин |

Какие данные создаются и что должно получиться в рекомендациях:

| Товар | SKU | Остаток | Продаж в день | Состояние | Купить, шт. |
| --- | --- | --- | --- | --- | --- |
| Кофе молотый | COFFEE-1 | 2 | 2 | Критично | 72 |
| Молоко 1л | MILK-1 | 5 | 3 | Критично | 106 |
| Хлеб белый | BREAD-1 | 30 | 3 | Нужна закупка | 81 |
| Сыр 200г | CHEESE-1 | 40 | 1 | В норме | 0 |
| Чай чёрный | TEA-1 | 12 | 0 | Нет продаж | 0 |

### Сборка для production

```sh
npm run build
```

Готовые файлы появятся в папке `dist/`. Их раздаёт веб-сервер (например, Nginx),
который также должен проксировать `/api` на backend.

## Как пройти по приложению

1. **Вход.** Откройте http://127.0.0.1:5173 и войдите как `demo@demo.ru` / `demo12345`.
   Можно и зарегистрироваться заново: ссылка «Зарегистрироваться» на странице входа.
2. **Дашборд.** Откроется сразу после входа: сколько всего товаров, сколько критических,
   сколько требуют закупки, и список того, что пора купить.
3. **Рекомендации.** Таблица с расчётом по каждому товару. Нажмите «Почему?» у строки —
   появится текстовое объяснение рекомендации. Фильтр сверху переключает «Нужна закупка» / «Все товары» / конкретное состояние.
4. **Товары.** Попробуйте поиск (например, `мол`), фильтр по категории (`Молочка`) и сортировку.
   Нажмите «+ Добавить товар» и создайте новый — откроется его карточка.
5. **Карточка товара.** Здесь можно:
   - отредактировать SKU, название, категорию;
   - изменить остаток на складе;
   - посмотреть продажи за 30 дней и записать продажи за любой прошедший день;
   - удалить товар (только если у него нулевой остаток и нет продаж — иначе backend не даст).
6. **Остатки.** Остатки всех товаров. Поменяйте число в строке и нажмите «Сохранить».
   Например, поставьте молоку остаток `200` — на дашборде оно перейдёт в «В норме».
7. **Продажи.** Выберите период и товар — увидите сводку и список продаж по дням.
   Кнопка «+ Записать продажи» добавляет продажи за день.
8. **Профиль.** Данные пользователя и организации. Кнопка «Выйти» внизу меню завершает сессию.

> Рекомендации считаются по продажам за 30 **завершённых** дней (до вчера включительно),
> поэтому сегодняшние продажи в расчёт не попадают.

```text
scripts/
└── seed-demo.js    заполнение backend демо-данными (npm run seed)
src/
├── api/            запросы к backend, по файлу на раздел (auth, products, inventory, sales)
├── assets/         общие стили
├── components/     переиспользуемые компоненты (формы, таблицы, пагинация, меню)
├── composables/    общая логика для нескольких страниц (загрузка данных для анализа)
├── router/         маршруты и проверка авторизации
├── stores/         состояние авторизации (токен, пользователь, организация)
├── utils/          вспомогательные функции: даты, форматирование, ошибки, формула рекомендаций
├── views/          страницы приложения
├── App.vue         корневой компонент с макетом
└── main.js         точка входа
```

### Как это устроено

1. После входа backend возвращает JWT-токен. Он сохраняется в `localStorage` ([src/stores/auth.js](src/stores/auth.js)).
2. Перед каждым запросом axios добавляет токен в заголовок `Authorization` ([src/api/http.js](src/api/http.js)).
3. Если сервер отвечает `401`, сессия очищается и открывается страница входа.
4. Роутер не пускает на внутренние страницы без входа ([src/router/index.js](src/router/index.js)).
5. Записи в backend защищены полем `version`: при изменении нужно передать текущую версию.
   Если кто-то успел изменить данные раньше, сервер вернёт ошибку `VERSION_CONFLICT`.
